① 端口转发（网络层，像 Bitvise）

  • 决定：哪些工具通到这台主机、用哪个端口
  • 连接主机时自动建立，断开就没了
  • 和 Claude 毫无关系，只是把端口打通

② 注册到 Claude（配置层）

  • 决定：在哪个作用域（全局 / 某个项目）登记、叫什么名字
  • 写一次就一直在 ~/.claude.json 里
  • 前提：对应端口已经转发，不然 claude 连不上
所以 端口 只属于 ①，名字 只属于 ②。现在的问题是两者挤在同一张表、还被做成「第 1 步 → 第 2 步」的向导。

4现在 vs 改后

现在

  1. 编辑主机里有工具表（启用 / 云端名字 / 端口）
  2. MCP 弹窗「第 1 步 选择工具」又是同一张表
  3. 「下一步：写入 Claude」只能写第 1 步勾的那些
  4. 名字（注册用）和端口（转发用）混在第 1 步
  5. 像向导，感觉每次都要从第 1 步走到第 2 步

改后

  1. 编辑主机只剩一个开关
  2. 「端口转发」页：只管启用 + 端口，连接时自动生效
  3. 「Claude 注册」页：只管作用域 + 名字，随时增删
  4. 两页平级，互相只有一个依赖：没转发的不能注册（给快捷按钮）
  5. 主机上不再单独存名字覆盖，名字在注册时决定
